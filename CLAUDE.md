# Astrophotography Portfolio

Dark, space-themed portfolio for the owner's astrophotos (Hasnaine Ahmed Dihan, Sydney). Beginner-friendly bootcamp project: code is heavily commented in plain language; keep that style.

- **Frontend:** React 18 + Vite 5 (ES modules), plain CSS. Dev server on `:5173`.
- **Backend:** Node + Express 4 + Multer (CommonJS). API on `:5001` (5000 clashes with macOS AirPlay).
- **No database:** photo metadata lives in `backend/data/photos.json`, images in `backend/uploads/`.
- **Two modes:** local (full CRUD via backend) and published read-only static site on GitHub Pages (no backend).

## Commands (run from this folder)

| Command | What it does |
| --- | --- |
| `npm run install:all` | Install root, `backend/`, `frontend/` deps |
| `npm run dev` | Start backend + frontend together (concurrently) |
| `npm run start:backend` | Backend only |
| `npm run build:static` | `export` then Vite build in `static` mode -> `frontend/dist/` |
| `npm run preview:static` | Preview the built read-only site locally |
| `npm run deploy` | `build:static`, then push `frontend/dist/` to `gh-pages` branch |

There are no tests and no linter configured.

## Layout

```
backend/
  server.js                  Express app, CORS (allows only localhost:5173 / 127.0.0.1:5173), error handler
  routes/photoRoutes.js      GET/POST /api/photos, PUT/DELETE /api/photos/:id
  controllers/photoController.js   read/write photos.json; photo = { id, title, description, filename, uploadDate }
  middleware/upload.js       Multer: jpg/jpeg/png/webp/tif/tiff, 25 MB max, random filenames
  data/photos.json           the "database"
  uploads/                   image files (gitignored except .gitkeep)
frontend/
  src/App.jsx                owns photos state; Header, UploadForm, Gallery, Lightbox
  src/components/            Header, UploadForm, Gallery, PhotoCard, Lightbox
  src/services/api.js        ALL backend calls + READ_ONLY flag + imageUrl()
  src/config/profile.js      name/email/Instagram/location shown in header
  src/styles/variables.css   theme colors/fonts; global.css for the rest
  .env.static                VITE_READ_ONLY=true (used by `--mode static`)
  public/photos(.json)       generated by export script; dist/ is build output
scripts/export-static.js     copies backend data+uploads into frontend/public (newest first, skips missing files)
```

## How the two modes work

- `READ_ONLY = import.meta.env.VITE_READ_ONLY === 'true'` in `api.js`. In static builds, photos load from `${BASE_URL}photos.json` and images from `${BASE_URL}photos/<file>`; `App.jsx` hides `UploadForm`; Gallery/PhotoCard should hide edit/delete controls.
- `vite.config.js` uses `base: './'` so the build works under `username.github.io/repo`.
- `frontend/public/photos*` and `frontend/dist/` are generated. Never hand-edit them; re-run `npm run build:static`.

## Conventions

- Backend is CommonJS (`require`); frontend is ESM (`import`). Don't mix.
- All fetch calls go through `request()` in `api.js`; components never call `fetch` directly.
- Colors/fonts only via CSS variables in `variables.css`.
- Keep the top-of-file comment on each file describing its purpose, and keep comments simple and explanatory.
- Changing the backend port means updating **both** `PORT` in `backend/server.js` and `API_URL` in `frontend/src/services/api.js`; changing the Vite port means updating the CORS origins in `server.js`.
- Uploaded filenames are `<timestamp>-<hex>.<ext>`; `removeImage` uses `path.basename` to prevent path traversal. Preserve that.

## Gotchas

- Browsers can't display `.tif`; it uploads but shows broken. Users should export JPG/PNG.
- `backend/uploads/` images are gitignored, so photos only reach the published site via `export` -> `frontend/public/photos`.
- The inner folder has its own `.git` (nested inside the parent `test` repo, which sees it as untracked). `graphify-out/` is gitignored.
- `profile.js` contains the owner's real personal details; don't change them unless asked.
