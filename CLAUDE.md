# Astrophotography Portfolio

Dark, space-themed portfolio for the owner's astrophotos (Hasnaine Ahmed Dihan, Sydney). Beginner-friendly bootcamp project: code is heavily commented in plain language; keep that style.

- **Frontend:** React 18 + Vite 5 (ES modules), plain CSS. Dev server on `:5173` (strictPort). Only one localhost.
- **Admin backend:** Cloudflare Worker in `admin-worker/` (ES modules, Wrangler 4). Commits changes to GitHub via the REST API.
- **No database:** photo metadata lives in `frontend/public/photos.json`, images in `frontend/public/photos/`, both committed to the repo.
- **Deploy:** `.github/workflows/deploy.yml` builds on every push to `main` and publishes `frontend/dist` to the `gh-pages` branch (peaceiris/actions-gh-pages). Worker commits trigger it too.
- Live site: https://dihanahmed.github.io/astrophotography/ (repo `dihanahmed/astrophotography`, public).

## Commands (run from this folder)

| Command | What it does |
| --- | --- |
| `npm run install:all` | Install `frontend/` and `admin-worker/` deps |
| `npm run dev` | Vite dev server on http://localhost:5173 |
| `npm run build` | Vite build -> `frontend/dist/` |
| `npm run worker:deploy` | `wrangler deploy` the Worker |

No tests or linter configured. To test the Worker locally: put dummy secrets in `admin-worker/.dev.vars` (gitignored) and run `npx wrangler dev` in `admin-worker/`.

## Layout

```
admin-worker/
  src/index.js        all Worker routes: /login, /photos (GET/POST), /images, /photos/:id (PUT/DELETE)
  wrangler.toml       non-secret vars: GITHUB_OWNER/REPO/BRANCH, ALLOWED_ORIGINS
frontend/
  src/App.jsx         hash router: '#/admin' -> AdminPage, else HomePage
  src/components/     HomePage, PageNav (filters + Admin link), Header, Gallery, PhotoCard (read-only), Lightbox,
                      AdminPage, LoginForm, AdminPanel, AdminPhotoCard, UploadForm
  src/services/api.js ALL network calls, token storage, imageUrl()/githubImageUrl()
  src/config/admin.js WORKER_URL (not secret), GITHUB_REPO/BRANCH
  src/config/profile.js  name/email/Instagram/location shown in header
  src/styles/variables.css  theme colors/fonts; global.css for the rest
  public/photos(.json)      the photo data; written by the Worker (hand-edits are OK but go through git)
.github/workflows/deploy.yml
```

## How admin works

- Secrets (Worker only, via `wrangler secret put`): `GITHUB_TOKEN` (fine-grained, Contents RW on this repo), `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET`.
- `/login` returns an HMAC-signed token `<base64url {exp}>.<sig>`, valid 7 days; frontend stores it in localStorage. Wrong passwords: growing delay + per-IP lockout (in-memory, per isolate).
- Upload = 2 calls so the Worker never decodes images (free plan CPU limit): browser base64-encodes the file and POSTs `{"encoding":"base64","content":...}` to `/images`, which the Worker pipes through a `FixedLengthStream` to GitHub `git/blobs`; then `POST /photos` with the blob sha commits image + photos.json in ONE commit (git trees API, retries on non-fast-forward).
- Upload progress uses XMLHttpRequest in `api.js` (fetch can't report upload progress).
- Admin panel lists photos via the Worker and shows images from raw.githubusercontent.com, so it's current before the site redeploys.

## Conventions

- Frontend and Worker are both ESM. All network calls go through `api.js`; components never call `fetch` directly.
- Colors/fonts only via CSS variables in `variables.css`.
- Keep the top-of-file comment on each file describing its purpose, and keep comments simple and explanatory.
- Changing the Vite port or the site URL means updating `ALLOWED_ORIGINS` in `admin-worker/wrangler.toml` and redeploying the Worker.
- Uploaded filenames are `<timestamp>-<hex>.<ext>`, generated by the Worker; delete only removes plain filenames inside `frontend/public/photos/`. Preserve that.
- Images are never resized/recompressed; 25 MB max (checked in UploadForm and the Worker).

## Gotchas

- Browsers can't display `.tif`; it uploads but shows broken. Users should export JPG/PNG.
- Locally, the homepage reads `frontend/public/photos.json` from disk: `git pull` after admin changes to see them.
- Every uploaded image stays in git history even after deletion (repo grows over time).
- The inner folder has its own `.git` (nested inside the parent `test` repo, which sees it as untracked). `graphify-out/` is gitignored.
- `profile.js` contains the owner's real personal details; don't change them unless asked.
